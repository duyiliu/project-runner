# 跨项目运行管理参考

## 8. 跨项目管理（manager.mjs，多项目/跨会话）

定位：全局安装一次本 Skill 后，在任意业务目录用同一数据目录（默认 `~/.project-runner/`）查看与管理**由本 Skill 启动并记录**的应用进程（Java/Python/Node/其他真实进程同理）。不是全机进程管理器；IDEA/手工命令行/Docker 启动的进程一律不接管、不停止，只可在端口冲突诊断时查看。统一入口（路径按实际安装位置解析，无需 cd 到业务目录）：

```bash
node "<安装目录>/scripts/manager.mjs" [--home <隔离数据目录>] [--json] <命令>
# list | status <别名|appId> [--probe] [--ready] | start <别名|appId> [--ack-unresolved <runId>] | stop <别名|appId> [--tree] [--grace <ms>] | restart <别名|appId> [--force] [--tree] [--grace <ms>]
# remove <别名|appId> [--ack-unresolved <runId>]　移除登记（须无存活受管实例；只删注册表条目，运行记录与日志证据保留）
# prune [--dry-run] [--apply]　回收超保留期批次日志/死锁残留/孤儿临时文件（默认 dry-run，--apply 才删除）
# logs <别名|appId> [--lines N] [--stream stdout|stderr|both] [--run <runId>] [--follow] [--src <run:…|hint:<hash>|tmp:…>] [--list-sources]
# ui [--port N] [--open]　本地 Web 管理台（默认固定 127.0.0.1:8199，无令牌仅本机；--open 自动打开 URL，失败仅打印；地址可收藏但仅本机可达勿转发，Ctrl+C 退出）
# 内部入口（Agent 用）：detect --root <dir>（只读候选）| start-new --desc <file> [--ack-unresolved <runId>] | record-unmanaged --desc <file> [--log-hints p1,p2] | cleanup-wrapper <别名|appId>（仅 UNKNOWN 且 wrapper 身份完整；恢复边界见 4.1/4.2）
```

Agent 使用规程：

1. **首次启动（受管登记）**：先调用 `node "<安装目录>/scripts/manager.mjs" --json detect --root "<仓库根目录>"` 获取只读候选。detect 只扫描仓库证据，不登记、不启动、不写文件；逐项核对 `evidence`（命中的文件/规则名）与项目实际约定，对候选补齐/修正解释器、命令、入口、端口等尚未确定信息。候选只是草案，不能替代第 1/1A 节发现、第 3/4 节命令匹配与启动前检查；输出空数组时按原规程手工调查，不编造。确认候选适用于目标后，把经用户确认的启动描述写入临时 JSON 文件并调用 `start-new`。描述字段：`alias`（全局唯一别名，Windows 不区分大小写）、`root`/`cwd`（绝对路径）、`entry`（同仓库多应用时的入口标识，默认 `default`）、`mode`（`jrebel`|`java`|`python`|`node`|`proc`），受管形态二选一——**直连** `exe`+`args`，或**命令模式** `command`+`expectedImage`：
   - `exe`：**必须解析为真实可执行进程**。Windows：Java 为真实 JDK bin 的 `java.exe`（裸名 `java` 先取 `JAVA_HOME` 再查 PATH，Oracle javapath 转发 shim 会被拒绝——shim 让真实 JVM 变成子进程导致日志句柄不落地、终止错位）；Python 为 venv/真实 `python.exe`；Node 为 `node.exe`+入口 js；`.cmd`/`.bat`/`.ps1` 包装与 WindowsApps 0 字节 stub 一律拒绝。Linux：真实 ELF/可执行文件（通常无扩展名，如 `node`/`java`/`python3`），要求普通文件且有可执行位；`#!` 脚本包装被视为 shell/解释器子进程，直接拒绝；`.cmd`/`.bat`/`.ps1` 同样拒绝。
   - `command`：完整命令行字符串（`npm run dev`、`mvn spring-boot:run`、`.cmd`/`.ps1` 脚本、复合命令），manager 在 Windows 经 `cmd /d /s /c`、在 Linux 经 `/bin/sh -c` 拉起 wrapper 后按 PPID 后代发现目标；`expectedImage` 为目标进程映像基名（Windows `node.exe`/`java.exe`/`dotnet.exe` 等；Linux `node`/`java`/`dotnet` 等）；可选 `discoverTimeoutMs`（默认 45000，慢启动可调大至 120000）。后代唯一匹配 → 托管；**已知启动器单链折叠**：npm/pnpm/yarn/maven/gradle wrapper 与目标同映像且构成单链（wrapper→npm→app）时，剔除命令行命中已知启动器特征的祖先、折叠到真实目标；其余同映像多候选（目标自身派生同映像子进程、cluster/fork 分叉）→ `DISCOVERY_AMBIGUOUS` 拒绝并列清单（此时收编命令或转非受管）；wrapper 已退无目标 → `SPAWN_FAILED`；超时 → `DISCOVERY_TIMEOUT` 留证 UNKNOWN。logger 与 wrapper 均 detached，CLI 退出后继续运行；stdout/stderr 经 pipe 转发（已实测 `echo` 等内建命令与多行输出完整，见 #48/#50）。**直接写 `CONOUT$` 或使用 Windows 控制台 API 的进程不写 pipe，其输出不会进入批次日志（行为未定义）**；**不接受 args**（参数写进 command 本身）。
   - `args`（仅直连，字符串数组：Java 为 `-cp`/`-jar`+主类/参数含 JRebel agent 参数；Python/Node 为脚本/模块与参数）、`envRefs`（仅环境变量**名称**数组，值不落注册表；声明依赖宿主提供的变量）与 `env`（可选对象：合法变量名到字符串字面值，明文持久化到 registry 并在启动时覆盖当前环境同名值；**禁止存放机密**，机密走系统环境变量 + `envRefs`；human/JSON 状态回显值会截断）、`expectedPort`、可选就绪证据 `readyLogPattern`（当前批次 stdout/stderr 正则）与 `readyUrl`（http(s) GET 返回 <400 即就绪）。manager 按“持久化意图 → 启动 → 同句柄身份采集/后代发现 → 登记”原子执行；`start-new` 成功仅代表进程存活（`readinessUntested=true`），就绪与热加载仍按第 5 节用真实证据判定；配了就绪证据后可用 `status <ref> --ready` 让 manager 给出 READY/NOT_READY/UNTESTED 评估。
2. **非受管启动**：连命令模式都无法安全定位唯一目标进程（多服务编排触发 `DISCOVERY_AMBIGUOUS`、远端拉起、容器等）时，不伪造托管：向用户说明能力限制后按原授权执行脚本，再用 `record-unmanaged` 记录尝试与日志线索（`--log-hints` 传脚本输出的日志路径，只关联不迁移；非 Java 项目脚本日志按第 4 节放到 `.tmp/runner-local-*`）。用户明确要求“可自动托管”而当前方式做不到时，先报 `UNSUPPORTED_LAUNCH`，不偷偷降级。
3. **再次启动/跨目录**：已登记应用直接 `start <别名>` 复用保存的配置；返回 `CONFIG_INVALID` 说明路径或产物失效，只重新分析**该目标项目**，不全盘扫描。
4. **停止/重启**：仅受管实例可用。默认语义是**有界强制终止**（Windows 同句柄核验后 `TerminateProcess`；Linux 由 Python 3.9+ pidfd helper 锚定进程实例后核验 `boot_id:starttime` 与 exe 并发送 `SIGKILL`，pidfd 不可用时明确拒绝终止，不回退到有 PID 复用竞态的 `kill(pid)`；退出码 137 语义）。可选修饰：`stop --tree`/`restart --tree` 连带终止目标当时快照中的全部后代进程（命令模式 npm/vite 等防子进程孤儿占端口，#39；先核验目标身份，按 ppid 向下枚举当时仍在的子孙（含多级）并各自采集 pid+创建时间+映像，先终止目标并清理 wrapper，再对仍存活的后代逐个同法核验+终止（Windows 用与 `Terminate` 相同的同句柄核验+终止原语，Linux 复核 `/proc/<pid>` starttime 与快照一致才发 `SIGKILL`），返回 `treeKilled:[{pid,image}]`（并附 `killedPids`）；仅限目标后代，不向上爬、不碰外部进程；后代已自行退出则跳过不报错；快照期间新拉起或身份已变的后代漏网/跳过是已知限制）；`stop --grace <ms>` 先发优雅信号（Linux `SIGTERM`——与 `SIGKILL` 同一 pidfd 锚定核验；Windows `taskkill` 不带 `/F`——持有已核验句柄期间发起并等待退出，PID 复用窗口已关闭），`<ms>` 内退出即落账优雅退出，仍存活再回退强制终止。两者仍可组合（先优雅、超时后连带树强杀）。执行前向用户说明；`restart` 先确认旧实例退出才起新实例，`--tree`/`--grace` 可透传给停旧实例这一步。UNKNOWN/身份不明/外部进程一律拒绝并保留证据，不自动重试。
4.1 **未结记录与恢复（AC04，不得删账后再起）**：`current` 存在且 `phase` 为 `STARTING`（启动中断/pid 未采集）、`UNKNOWN`（如 `identity_capture_failed`，进程实际可能存活），或任何无法识别的 `phase`（记录被外部改坏等）时，`start`/`start-new` **默认拒绝**，退出码 3、错误码 `UNRESOLVED_RUN`，**不产生任何新进程**（runtime/registry 文件也不被改写）；错误信息给出 `runId`、证据文件（`--home` 下 `runtime/<appId>.json`）与日志路径，以及恢复指引。此时 `status` 仍展示未结记录全量证据（pid/创建时间/映像/日志/`lastError`），文本模式还会列出 `prevRuns` 及 `archiveReason`；`logs --run <旧runId>` 仍可查；**不要删除 runtime 记录或日志来绕过**。命令模式启动失败并留下 UNKNOWN 时，若记录含完整 wrapper 身份（`wrapperPid`+创建时间+映像），可先用 `cleanup-wrapper <别名|appId>` 只清理该 wrapper：它按记录身份核验后终止，**创建时间或映像任一不符即拒绝**；Linux 在发信号前先 `SIGSTOP` 冻结 wrapper 再复核身份（已 exec 成目标时 `SIGCONT` 恢复并返回不匹配），该 PID 已属目标候选时不会被清理；不改变 UNKNOWN 证据，也不清理目标候选或后代。**目标候选与后代必须按进程证据人工核验处置，禁止直接把 UNKNOWN 当 STOPPED 重试**；`cleanup-wrapper` 只处理 wrapper，`--ack-unresolved` 仍只属于 `start`/`remove`。
4.2 **显式人工核验后的恢复**：先由用户/AI 用 `status`、`logs --run <runId>` 及系统进程工具核验旧进程；确认已退出后执行 `start <别名> --ack-unresolved <runId>` 或 `start-new --desc <file> --ack-unresolved <runId>`。仅当 `runId` 与未结记录一致时生效，否则 `ACK_MISMATCH`；manager 会二次核验：
   - 未结记录有完整身份证据（pid + 创建时间 + 映像）且进程**仍存活** → 仍然拒绝（`UNRESOLVED_RUN`），禁止第二份实例；
   - PID 存在但缺完整身份证据、无法确认是否原实例 → 拒绝；
   - 核验已退出（或 PID 已复用），或 `STARTING` 且无 pid（无可核验对象）→ 归档旧账后正常启动，`prevRuns` 条目带 `archiveReason=abandoned-by-ack` 以及原 pid/身份/日志证据，绝不静默丢弃；
   - 当前没有 `STARTING`/`UNKNOWN` 未结记录时带 `--ack-unresolved` → `ACK_MISMATCH`（避免误用过期 runId）。
   成功启动的输出会带 `abandonedRunId`/`abandonedReason`，需向用户说明“旧账已被显式放弃、证据保留在 prevRuns”。
5. **状态解读**：`RUNNING`=进程存活（不等于业务就绪）；`STOPPED` 有退出证据；`STARTING`=启动进行中；`UNKNOWN`=中断/身份不可核验/非受管记录。`STARTING`/`UNKNOWN` 的受管记录属于未结记录，重启受 4.1/4.2 约束。PID/端口仅有证据才填写；JRebel 是否验证、业务是否就绪与本状态分开表述，不互相冒充。
6. **数据与安全**：注册表/运行记录在 `~/.project-runner/`（`registry.json`、`runtime/`、`logs/`、`locks/`），不进 Git、不进业务项目；损坏或不兼容版本会以退出码 5 拒绝操作并保留原件——此时报告用户人工处置，不要删文件重建。受管日志按启动批次（runId）保存在数据目录；项目脚本自己写的 `.tmp` 日志保持原路径原样。日志入口统一为 `manager ui`（网页，含日志源与文件树）与 `manager logs`（CLI，`--src`/`--list-sources` 复用与 ui 相同的统一日志源解析）。注册表不落 Token/密码/明文命令行；日志内容可能含敏感信息，外发前按既有规则检查。
6.1 **移除登记（remove）**：应用不再需要时用 `remove <别名|appId>` 从注册表移除。仅允许无存活受管实例时移除：current 为 RUNNING 且核验存活一律拒绝（退出码 3，`INSTANCE_RUNNING`，先 `stop` 再 `remove`）；STARTING/UNKNOWN 未结记录默认拒绝（`UNRESOLVED_RUN`），人工核验已退出后用 `--ack-unresolved <runId>` 显式放弃（规则同 4.2）。remove 只删注册表条目，`runtime/<appId>.json` 与 `logs/<appId>/` 证据一律保留；成功后 `list` 不再显示该应用，`status`/`logs` 按“未登记”报 NOT_FOUND（证据文件仍在数据目录，可人工查看）。不要用删 registry.json/runtime 文件的方式“移除”。
6.2 **残留回收（prune）**：`prune [--dry-run] [--apply]` 回收三类残留——`logs/<appId>/` 超保留期历史批次日志（保留 current 与 prevRuns（≤20，PREV_RUNS_KEEP）引用的 runId，其余回收）、`locks/*.lock.stale-*` 死锁回收残留、数据目录内 `.tmp-<pid>-<hex>` 原子写孤儿临时文件。**默认 dry-run** 只打印将删内容，确认后加 `--apply` 才真正删除；绝不删 current 运行日志与 runtime/registry 证据，绝不触碰数据目录之外的文件；运行记录损坏时按 DATA_* 契约整体拒绝（退出码 5），不删任何文件。逐应用在应用锁内判定，锁忙/损坏或缺 pwsh 时跳过该应用并注明；不要在 prune 之外手工批量删 `logs/` 下的文件。
7. **本地管理台（ui）与默认观察入口**：**受管启动（start/start-new）成功后，用户的默认观察入口是 `manager ui`**——它全局展示所有受管应用的状态与按批次日志；**ui 实例数量与项目数无关**：启动 N 个项目不会拉起任何 Web 进程，并行多项目也共用同一个 ui 实例（读共享数据目录，天然全局视角），不要为每个项目各开一个；受管日志在数据目录；原单项目 viewer 已移除，非受管日志线索、`.tmp` 兼容日志与项目文件树都在本台查看（见第 5 节）。本 Skill 每次被调用执行受管操作时都要确保 ui 已启动：以后台/detached 方式拉起 `node <安装目录>/scripts/manager.mjs ui [--port N]`（该命令前台常驻），交付固定地址 `http://127.0.0.1:8199`；已在运行（退出码 3 端口占用）时复用同一地址。**默认固定端口 8199**（`--port 0` 为随机端口）：重复启动会提示"已有 ui 实例占用"，直接复用或用 `--port` 换端口另起实例；8199 被其他程序占用时提示换端口。管理台只绑 `127.0.0.1`，无令牌，地址固定可收藏。管理台展示 list、status（含未结记录证据与 prevRuns）、日志（受管批次、非受管线索、`.tmp` 兼容日志）与所选应用的项目文件，详情卡提供受管应用的启动/停止/重启/移除按钮与非受管 STOPPED 登记的移除按钮（与 CLI 同一实现与安全边界，`POST /api/lifecycle`，所有操作均需再次点击确认；`stop` 是有界强制终止）；STARTING/UNKNOWN 未结记录在人工核验后也可从管理台执行“ack 并启动”（同 `start --ack-unresolved <runId>`），非受管启动仍走 CLI。地址仅本机可达且页面可启停受管应用，不得转发给他人或写入文件/聊天记录；用完 Ctrl+C 退出，不留常驻进程。数据损坏时管理台原样报错，处置方式同第 6 条。
8. **退出码**：0 成功；1 用法；2 未找到；3 状态冲突（已运行/别名占用/身份不明/配置失效/`UNRESOLVED_RUN`/`ACK_MISMATCH` 等）；4 环境依赖（缺 pwsh 7、`/proc` 不可读、Linux 安全停止缺 Python 3.9+/pidfd 或平台不支持）；5 数据损坏。`--json` 输出单一稳定对象（`schemaVersion/ok/command/data|error`），脚本化调用优先用它。
